Session 1

Serving metrics to tools and agents

  • Expose semantic-layer queries as tools of a protocol server
  • Take the caller's role from the credential, never from the request
  • Test the server for each role
01
Serving the layer

Dashboards, notebooks and agents should reach the metrics through one governed door

An API (REST)

For applications and dashboards; the credential is in an HTTP header.

A protocol server (MCP)

For assistants and agents: tools they can list and call, with typed inputs and outputs.

Same rules behind both. The row rules, masks and certified metrics of the layer, never a copy of them in the server.

The Model Context Protocol, specification version 2025-11-25 (modelcontextprotocol.io). Cube, dbt's semantic layer and others now offer MCP servers; the course writes one with the standard library to see every message. Building agents themselves is AE-302; here we only serve the layer.

servers/qamar_mcp.py, under 200 lines, no SDK. A tool error (an uncertified metric, a refused row rule) comes back as a result with isError true, so the model can read it and recover; protocol errors (unknown method) are JSON-RPC errors.

Lab 4.1, step 2

The role comes from the credential, never from the request

1 · Tokenin the server's environment (stdio) or an HTTP header
→
2 · DigestSHA-256, compared in constant time with the registry
→
3 · Roleapplied by the layer to every query of the session
Takeaway. An agent passes on whatever text reached it; a role it could claim is a role anyone could claim.

The MCP specification says a stdio server takes credentials from the environment, and an HTTP server uses the authorization flow. The registry holds digests, not tokens. The demo tokens in the lab are synthetic. Ask: what does one shared token for all agents lose? Rows by role, masks, and who asked.

Lab 4.2, step 1

Every figure travels with its metric, version, filters and grain

86.5% · Collection rate (certified) v1.0.0 (certified, Majdi Bawazir) · filters: time.month = DATE '2026-03-01' · grain: total

  • The reader sees which definition, so the Day 1 argument does not start again

The NDMO Business Intelligence and Analytics standards ask for documented, trusted reporting; an answer card is that documentation at the point of use. In the stretch, the same card in Arabic uses the metric's Arabic synonym as its name.

Lab 4.2, step 4

A refusal should say why, and offer the nearest certified answer

Uncertified

"Share of bills paid on time is a draft owned by Ebtihal Al-Ghanim and has no certified definition yet. The nearest certified metric is collection_rate."

Not matured

"Bills of that month have not reached 30 days past their due date, so their collection rate is not final yet. The latest final month is April 2026."

"I cannot answer that" teaches the manager nothing and sends them to a spreadsheet. A refusal that names the owner creates the right conversation: the draft gets certified, or the manager uses the certified metric knowingly.

Session 3

Which questions may go to the assistant

  • Estimate the wrong-figure rate by question type with an upper bound
  • Route each question type under a stated tolerance
  • Record the decision with its evidence and its review date
03
A decision, not a score

The committee states a tolerance; the evidence decides each type of question

Qamar's tolerance

At most 10% wrong figures for any question type Muhsi answers alone.

  • A wrong figure: plausible, visible, or a missed refusal
  • Not a wrong figure: an error or a wrong refusal (costly, but seen)
  • Measured by question type, with the guard on, over three runs

The tolerance belongs to the business, not to the data team. Ask the room what tolerance their own committee would state for a finance figure, and for a usage figure. Different types may deserve different tolerances; Qamar starts with one.

Lab 4.3, step 4

A routing policy is a risk decision, recorded with its evidence and its review

  • Owner, status and date
  • Context: the system, the set, the model (stand-in or live)
  • The tolerance in one sentence
  • Evidence: the table and a hash of the evaluation file
  • Decision, consequences, and when it is reviewed

National AI Risk Management Framework

SDAIA, April 2026, advisory: identify, assess, treat and monitor AI risks. The routes are the treatment; the review triggers are the monitoring.

Source: the framework's English executive summary (sdaia.gov.sa, document SDAIA-P145EN). Do not attribute specific thresholds to it: it gives the method, Qamar sets the tolerance. Review triggers: a model change, a major metric version, monthly.

Session 4

Design review

  • Review a semantic model and an evaluation with a checklist
  • Rank findings by likelihood and impact
  • Log the decisions a review panel takes
04
The design review

A panel reads a product through three lenses, then ranks what it finds

Correctness

Do the parts add up? Is each certified metric the agreed definition? Do the figures match certified answers?

Governance

Rows by role, fields by lineage, deny by default, refusals, routes on bounds, a decision record.

Portability

What runs only on one engine; what a second tool would leave behind (Day 2).

The capstone defence uses the same lenses. The panel's job is not to redesign the product, but to find what would hurt a manager, rank it, and agree who fixes what by when.
